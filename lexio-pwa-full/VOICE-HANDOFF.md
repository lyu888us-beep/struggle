## 下一窗口如何接上

1. 在平台指定分支的最新工作区，进入 `lexio-pwa-full`；运行 `node scripts/voice-queue.mjs` 对照计数，再运行 `node scripts/voice-queue.mjs --pending > /tmp/pending.jsonl`。已上传的句子不会再次输出。保留英文原文、标点、来源、目标文件名；遇到带数字、缩写或生僻人名的句子，核对读法后再录，不从队列删除。
2. 句子只用原聊天选定的美式 `voice-00`，正常语速，不用系统音替代。参见 [音源档案](media/voice/README.md)，试听锚点 `media/voice/card-1.mp3`。**音色 ID 只在原会话获选后有效；新窗口同名 ID 不证明是同一个声音。** 若新窗口不能访问原音色，先告诉用户并确认能否回原会话或恢复相同声音，不要擅自重新选声。单词英美读音不改。
3. 选本批未录原句，用 JSON 二维数组保存各段的队列行，每组严格按原文顺序生成一段 WAV（`b0.wav` 等）。每次对话最多 10 段、每段不超过 1,500 字符。v30 每段 18 句、共 10 段；后续按句长调整。临时 WAV、队列和工具环境不上传。
4. 离线切分：在 Python 环境安装 `numpy pocketsphinx imageio-ffmpeg`；执行 `python scripts/cut-voice-batch.py groups.json wav_dir staging_dir`。数字需先明确口头读法，未知词需补发音。切点有疑问时优先核验波形和原文；脚本允许第四个参数传已核对的切点 JSON。**未对齐或静音不要发布。** 输出为暂存 MP3 和 `clips.json`；这一步不会修改线上映射。
5. 检查本批键均不在旧 `selectedRecordings` 中；将 MP3 复制到 `media/voice`，把 `clips.json` 合入 `index.html` 的完整文本映射，更新 `sw.js` 的 `bulkAssets`、缓存版本及相应测试。不要覆盖旧录音、变更词条 ID、或移除未录的文字。
6. 运行 `npm test`、`node scripts/voice-queue.mjs`、`git diff --check`。核对新增文件数、媒体可播放性、剩余数量；更新此表与声音档案。提交并推送当前工作分支，检查此次提交对应的 Pages 工作流成功后再通知用户。
