# 乐词声音档案

| 用途 | 当前发布设置 |
| --- | --- |
| 读单词 | 当前有 **418 个本地单词音频**（清单：`word-audio-manifest.json`），美音 `en-US` 优先播放 `voice-00` MP3。五个样音由用户试听认可；其余 413 个经自动对齐，尚未逐条人工听检。未录单词仍不读取词条自带的 `us` 录音：iPhone/iPad Safari 在点击手势内先请求有道 `dictvoice type=2`；若远程媒体失败或超时，改用系统 `en-US` 语音。其他设备优先使用浏览器语音合成，并在当前页面会话内锁定一个可用的美式音色。系统语音跨设备不保证同一说话人。英音 `en-GB` 仍优先词条 `uk` 录音，否则使用有道 `dictvoice type=1`；失败后使用设备英音。语速均为 1×。 |
| 读句子 | **Arena 对话中已选 `voice-00`**，美式英语 `en-US`，1×。已有 MP3 为音色参考（例：`card-1.mp3`、`daily-1.mp3`）。该 ID 属于原会话，不是可在任意语音服务使用的模型名称。只按完整英文匹配录音，无录音时保留文字，不切换系统声音。 |

当前 `media/voice/` 共 **18,462 个 MP3 文件**（原有 17,569 个 + 累计新增 893 个）。累计新增包含 472 个缺录词典短语、3 个精确改写例句、5 个用户确认样音和 413 个队列单词音频。所选语音离线清单同步包含已发布文件。

词库中有 28,414 条内置词条；当前 `.tmp-voice/words-unique.json` 只包含 9,830 条唯一词条队列，不能据此宣称 20,000+ 全库音频已完成。

## 批量单词录音状态

- 词条清单 `word-audio-manifest.json` 记录全部 418 个已发布单词映射。
- 本批用 10 个 `voice-00 / en-US` 合并音频覆盖 1,423 条尚未录制的队列项；PocketSphinx 只在有安全静音切点的组中成功切出 **403 个**独立词条 MP3（来源组 0、1、3）。其余 7 组共 1,020 条虽有临时合并音频，但切点检查发现无可靠静音；未切片、未加入映射、未发布。临时合并音频不算单词 MP3，也未逐条人工听检。
- 因此，批量 TTS 能显著减少逐词请求，但不能把所有组数直接当成独立成品数。后续先改善或验证分组停顿／切分质量，再发布；不得强行在语音中间切开。
- 当前页面缓存版本 `lexio-shell-v118-word-audio-batch-002`。JSDOM 自动测试模拟了 iOS 远程媒体失败后转用系统 `en-US` 的路径；这不是 iPhone 16 Pro Max／iOS 27 真机验证。

原有录音覆盖 11 个场景全部 1,100 条日常与商务口语，以及部分词卡例句；每条口语都对应本地完整 MP3。口语扩充批 989 条：89 条商务表达为连续录制后按原文对齐切分；900 条句型练习中 200 条整句录制，700 条用同一 `voice-00` 的句型前半句和任务短语组合（保留陈述／疑问语调，切口淡入淡出），不是设备合成，也不是换另一个人读。严格按原英文建立映射，重复的英文共享录音。

核对范围为内置词库、演示词卡、日常及商务口语，按程序当前可朗读的文本规则剔除词典残句、去重；不包含用户外部导入的词库。

从 `lexio-pwa-full/` 运行：

```
node scripts/voice-queue.mjs                      # 实时统计
node scripts/voice-queue.mjs --pending > /tmp/pending.jsonl  # 每行给出原文、来源、建议文件名
```

后续录制必须沿用同一个已选声音；生成实际 MP3 后，再登记到 `index.html` 的 `selectedRecordings`（单词样音用 `selectedWordRecordings`）和 `sw.js` 的 `bulkAssets`。不要把未生成或未安全切片的文件登记成可播放。`npm test` 校验录音、离线清单和媒体范围请求。
